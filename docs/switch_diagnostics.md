# Switch Diagnostics And Cross-Task Plots

This document explains the switch-comparison plots generated by:

```bash
conda run -n Nowcasting python scripts/analysis/16_plot_switch_diagnostics.py \
  --config configs/switch_diagnostics.yaml
```

The script does not train models and does not recompute model predictions. It
reads the already saved task-specific switch comparisons and produces diagnostic
figures for inspection.

## Output Layout

Intra-task diagnostic figures are saved under:

```text
results/comparisons/switch_diagnostics/<task>/<selection>/<method>/figures/
```

Cross-task figures are saved inside the matching cross-task comparison:

```text
results/comparisons/cross_task_switch/<selection>/<comparison>/figures/
```

The navigation manifest is:

```text
results/comparisons/switch_diagnostics/plot_manifest.csv
results/comparisons/switch_diagnostics/reports/switch_diagnostic_plot_navigation.md
```

## Intra-Task Plots

`event_timelines/`

Shows one method at a time on selected events. The top panel is the true
`Signal` with the threshold. The switch panel compares `Perfect Switch`, raw
model switch, and final post-processed model switch. Use it to understand
whether errors come from the model decision itself or from switch
post-processing.

`task_specific/horizon_error.png`

Autoregressive only. Shows MAE and RMSE by forecast horizon step. It answers
whether the model gets worse as the prediction moves farther into the future.

`forecast_examples/`

Autoregressive only. Shows past context, true future, and predicted future in
raw signal scale for selected windows. Use these plots to inspect whether a
forecast crosses the operational threshold for the right reason.

`task_specific/duration_predicted_vs_true.png`

Current-level persistence only. Scatter plot of true versus predicted remaining
persistence duration in minutes. Points near the diagonal are good; systematic
compression toward low durations or very large scatter indicates weak duration
regression.

`task_specific/duration_absolute_error_distribution.png`

Current-level persistence only. Histogram of absolute duration errors in
minutes, clipped at the 99th percentile for readability.

`task_specific/probability_calibration.png`

Long-fade detection only. Reliability curve for `P(long_fade)`. The diagonal is
ideal calibration. Points above or below the diagonal indicate underconfidence
or overconfidence.

`task_specific/probability_distribution.png`

Long-fade detection only. Distribution of predicted long-fade probabilities.
It helps identify models that output almost all probabilities near 0, near 1,
or around the decision threshold.

`task_specific/survival_probability_calibration.png`

Survival persistence only. Reliability curve for survival probability at the
configured horizon, currently 300 seconds.

`task_specific/survival_probability_distribution.png`

Survival persistence only. Distribution of predicted survival probabilities at
the switch horizon.

`task_specific/survival_curves.png`

Survival persistence only. Displays selected survival curves
`S(u | X_t)` across saved horizons. A valid survival curve should stay between
0 and 1 and should not increase with horizon.

## Cross-Task Plots

`global_metrics/`

Horizontal bar charts for F1, precision, recall, and balanced accuracy. There
is one plot for the common reference-grid denominator and one for the strict
timestamp-intersection denominator.

`precision_recall/`

Scatter plot of recall versus precision. Marker size represents native decision
coverage on the reference grid. This is useful because a method can look good
on precision/recall while covering fewer operational timestamps.

`coverage/`

Shows how much of the common reference grid each method natively covers. The
annotation reports how many Perfect-Switch-positive samples have no native
decision for that method.

`raw_vs_postprocessed/`

Compares the number of raw positive switch samples with the number of final
post-processed positive samples. This is the first plot to inspect when a
method looks suspiciously aggressive or conservative.

`event_heatmaps/`

Shows per-event F1 on the common reference grid. Rows are methods; columns are
events. This identifies whether a model performs consistently or only on a few
easy events.

`event_timelines/selected_methods/`

Readable cross-task event timelines with a limited number of methods, selected
from the best methods while keeping task diversity.

`event_timelines/all_methods/`

Complete cross-task event timelines with all included methods. These plots are
larger and less readable, but useful for debugging and checking whether a method
was omitted from the selected timeline.

In cross-task timelines, filled bands are the post-processed switches and black
ticks are the raw switch activations before post-processing.

## Metric Denominators

Cross-task comparisons use two denominators:

- `reference_grid_missing_as_zero`: evaluates every method on the common
  autoregressive Perfect Switch grid. Missing native method decisions are filled
  with `0`, so lack of coverage is penalized.
- `strict_common_timestamp_intersection`: evaluates only timestamps where every
  included method has a native decision. This is useful as a conditional
  diagnostic, but it hides coverage differences.

For final operational comparison, prefer the reference-grid table and plots.
